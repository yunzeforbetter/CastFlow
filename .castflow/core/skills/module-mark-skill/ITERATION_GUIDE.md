## When to edit

- A stance is added or removed (feature, shared method, independent system, framework mechanism): edit the duties in SKILL.md, the question text in EXAMPLES.md, and `stances` in marks.schema.json.
- The test for attach, split, or keep changes: edit Rules 2 and 3 in SKILL_MEMORY.md, and the matching action in EXAMPLES.md.
- Jev's question types change, or the rule "do not invent a probability when Jev was not called" changes: edit Rule 4 and Pitfall 4. Do not write one language's directories into criteria.
- The user corrects a class of bad attach (a shared directory treated as a feature, or a mechanism swallowing surfaces): edit the rule and one example first. Do not write that repo's paths into this skill.

## Confirm

- The description is still the mark duty, a Use when, and one NOT, and that NOT is not the body of some programmer skill.
- The four actions in EXAMPLES match `action` in the schema.
- The skill does not turn one product's directory layout into a general rule.
